# Аудит реализации chat-openwebui

Дата: 2026-07-14

## Исправлено

- Python Dockerfile больше не пытается установить пакет до копирования исходников.
- OpenAI-compatible streaming использует корректные SSE-кадры без двойного `data:`.
- Добавлен `GET /v1/models`, необходимый для обнаружения модели интерфейсом OpenWebUI.
- TS-шлюз стал прозрачным прокси и больше не имитирует использование AI SDK пустым вызовом.
- Путь к `config/providers.yaml` корректно разрешается локально и в контейнере; запись выполняется атомарно.
- Полный URL `/chat/completions` нормализуется перед передачей в `AsyncOpenAI`, чтобы SDK не дублировал путь.
- Отсутствующий API-ключ теперь даёт понятную ошибку, а не отправляет имя env-переменной как ключ.
- Ошибки параллельных веток LangGraph агрегируются редьюсером и не конфликтуют в state.
- Router использует свой YAML `base_prompt`, а не полностью игнорирует конфигурацию.
- Тексты найденных точек гидратируются из payload Qdrant, поэтому dense retrieval работает после рестарта процесса.
- Базовый compose стал CPU-first; NVIDIA reservations вынесены в `docker-compose.gpu.yml`.
- Добавлен CI: pytest, TypeScript typecheck/build, проверка compose и Docker-сборки.

## Подтверждённые расхождения со спецификацией

Эти пункты не следует отмечать выполненными до отдельной реализации:

1. `LangServe` заявлен как транспорт Python-движка, но runtime использует собственный FastAPI endpoint `/v1/chat/completions`.
2. `LlamaIndex` и пакет `langsearch` заявлены в стеке, но текущий runtime их не использует.
3. `@ai-sdk/openai-compatible` является клиентским provider adapter, а не formatter OpenAI-compatible server responses. TS-шлюз сейчас корректно работает как прозрачный HTTP/SSE proxy.
4. Управление провайдерами изменяет YAML, но Python-движок кэширует конфигурацию. Для применения изменений пока нужен рестарт `py-engine`.
5. `MongoStore` написан, но не подключён к основному графу и не участвует в обработке запросов.
6. Все манифесты-настроения одного агента одновременно добавляются в prompt. Механизма выбора активной призмы нет.
7. В граф передаётся только последнее пользовательское сообщение. Полная история чата OpenWebUI пока теряется.
8. Реальный ColBERT sidecar и полный smoke flow OpenWebUI -> gateway -> engine -> provider не проверены.
9. `uv.lock` отсутствует, хотя старый чек-лист утверждает обратное; Python-зависимости не зафиксированы lock-файлом.

## Критерий готовности следующего этапа

- CI зелёный на чистом checkout.
- CPU compose действительно поднимается без NVIDIA runtime.
- OpenWebUI видит `agentic-circuit` через `/v1/models` и получает валидный stream.
- Изменения provider config либо применяются горячо, либо endpoint явно возвращает `restart_required: true`.
- Выбрана одна фактическая архитектура: LangServe invoke/stream или внутренний OpenAI-compatible FastAPI API; документация и код не должны описывать оба варианта одновременно.
